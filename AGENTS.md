# Правила роботи Codex

Ці правила діють для всього репозиторію Vitaris Brand Lab.

## Архітектура

- Використовувати спільні компоненти з `shared/components/`.
- Не дублювати спільну дизайн-систему в директоріях брендів.
- Зберігати контент окремо від дизайну та дизайн-токенів.
- Дотримуватися однакової структури всіх продуктів.
- Не змінювати назви директорій без погодження з користувачем.
- Спільні шаблони розміщувати у `shared/templates/`, а відмінності бренду описувати через `brands/<product>/design/brand-tokens.json`.

## Графічні ресурси

- Спільні корпоративні ресурси зберігати у `shared/assets/`, а ресурси конкретного продукту — у `brands/<product>/assets/`.
- Оригінальні корпоративні логотипи зберігати у `shared/assets/logos/originals/`.
- Не переміщувати, не перейменовувати, не перезаписувати й не модифікувати оригінальні графічні файли без окремого погодження.
- Зберігати оригінали окремо від згенерованих матеріалів; згенеровані результати розміщувати в `exports/`.
- Не деформувати логотипи й зображення паковання та зберігати їхні оригінальні пропорції.
- Реєструвати продуктові ресурси у `brands/<product>/assets/asset-manifest.json`; не вигадувати відсутні метадані.
- Перед додаванням бінарного файлу до Git перевіряти його розмір. Для файлів понад 50 MB повідомляти користувача й пропонувати Git LFS окремим рішенням, не встановлюючи його без дозволу.

## Контент

- Основна мова матеріалів — українська.
- Не вигадувати склад, дозування, показання, спосіб застосування чи клінічні результати.
- Використовувати перевірені джерела та зберігати посилання на них поруч із відповідними даними.
- Чітко розрізняти наукові дані про окремі інгредієнти та дослідження готового продукту.
- Не формулювати твердження про лікування захворювань без належного наукового й регуляторного обґрунтування.
- Враховувати регуляторний статус продукту та країну поширення матеріалу.
- Якщо даних недостатньо або вони потребують перевірки, залишати явний `TODO`.
- Не переносити твердження з одного продукту на інший без окремої перевірки.

## Дизайн

- Дотримуватися принципу Mobile First.
- Надавати пріоритет читабельності й достатньому контрасту.
- Не зменшувати шрифт, щоб умістити надмірний обсяг тексту.
- За потреби розділяти інформацію на декілька карток.
- Використовувати спільні дизайн-токени з `shared/design-system/`.
- Підтримувати індивідуальний стиль кожного бренду через його бренд-токени.
- Орієнтувати навчальні картки на формат 1080 × 1920 px зі співвідношенням 9:16.

## Робочий процес

- Перед змінами аналізувати наявну структуру та локальні правки.
- Не видаляти файли без необхідності.
- Не встановлювати залежності, якщо вони не потрібні для поточного завдання.
- Не виконувати `git push` без прямого дозволу користувача.
- Не створювати Git-коміти без підтвердження користувача.
- Після виконання завдання перевіряти змінені конфігурації та дані.
- Після виконання завдання надавати короткий звіт про зміни й перевірки.

## Mandatory Task Reporting

- Після кожного завдання створювати один підсумковий Markdown-звіт, якщо користувач прямо не попросив окремі звіти для логічних етапів.
- Зберігати історичний звіт у `reports/history/` з назвою `YYYY-MM-DD-NNN-task-slug.md`.
- Використовувати наступний доступний послідовний номер `NNN` у межах дня та ніколи не перезаписувати історичні звіти.
- Оновлювати `reports/latest.md` повним вмістом останнього історичного звіту.
- Використовувати українську мову для звітів.
- Створювати звіт також для частково виконаного або невдалого завдання, якщо файл можна записати.
- Фіксувати лише фактично виконані дії та перевірки.
- Не приховувати помилки, невдалі перевірки, невиконані перевірки або відомі обмеження.
- Перелічувати створені, змінені та видалені файли шляхами від кореня проєкту.
- Не включати секрети, токени, паролі чи персональні дані.
- Не включати повні великі файли коду без необхідності.
- Не створювати окремий звіт для технічної операції створення або оновлення самого звіту; вона є частиною поточного завдання і не запускає новий цикл звітування.
- Наприкінці відповіді Codex вказувати шлях до останнього звіту.
