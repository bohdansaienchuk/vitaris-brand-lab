# Звіти про завдання Codex

Каталог містить звіти, достатні для перевірки результатів і передачі контексту іншому AI-асистенту.

## Структура

- `latest.md` — повний вміст останнього історичного звіту.
- `history/` — окремий незмінюваний звіт для кожного завдання.

## Іменування

Історичний звіт має назву `YYYY-MM-DD-NNN-task-slug.md`, де:

- `YYYY-MM-DD` — локальна дата виконання;
- `NNN` — наступний доступний тризначний номер у межах цієї дати;
- `task-slug` — коротка англомовна назва завдання у kebab-case.

Перед створенням звіту потрібно переглянути файли за поточну дату. Наявний файл не можна перезаписувати: якщо номер зайнятий, використовується наступний.

## Обов'язковий процес

1. Після завершення роботи визначити статус: `completed`, `partial` або `failed`.
2. Створити один історичний звіт за шаблоном нижче.
3. Записати його повний незмінений вміст у `latest.md`.
4. Перевірити ідентичність обох файлів.
5. Наприкінці відповіді користувачу вказати шлях до історичного звіту.

Звіт створюється навіть для часткового або невдалого завдання, якщо файлова система доступна для запису. Створення та синхронізація звітних файлів є частиною поточного завдання і не вважається новим завданням, тому не створює рекурсивного циклу звітів.

## Шаблон

```markdown
## Task Information

- Date:
- Task ID:
- Task name:
- Status: completed / partial / failed

## Objective

Короткий опис мети завдання.

## Completed Work

Що фактично реалізовано.

## Files Changed

Створені, змінені та видалені файли зі шляхами від кореня проєкту.

## Architecture Decisions

Прийняті технічні рішення та їх обґрунтування.

## Validation

- Виконані команди.
- Результати перевірок.
- Кількість успішних і невдалих тестів.
- Перевірки, які не виконувалися.

## Issues and Limitations

Проблеми, обмеження та невирішені питання.

## Next Steps

Рекомендовані наступні дії.

## Handoff Notes

Контекст, необхідний іншому AI-асистенту.
```

## Вимоги до змісту

- Писати українською мовою та фіксувати лише фактично виконане.
- Не приховувати помилки або пропущені перевірки.
- Не включати секрети, токени, паролі чи персональні дані.
- Не вставляти повні великі файли коду без необхідності.
- Для кількох етапів одного завдання створювати один підсумковий звіт, якщо користувач не попросив інакше.
